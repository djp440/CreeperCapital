# 组合式指数价格模型与配置文件定义的合约

指数价格由一个**在对数空间里演化**的组合式随机模型生成，价格天然恒正：`ln P = ln F + 慢偏离 + 跳跃偏离`。其中 **基本面价值 F** 缓慢漂移（漂移方向由**市场状态**决定，并向合约起始价格缓慢回归，长期不发散）；价格围绕 F 均值回归（日常扩散的偏离回归得慢，跳跃留下的偏离几小时内回吐大半）；扩散项服从 Student-t（肥尾），强度按 GARCH(1,1) 聚集；**跳跃**按泊松到达、幅度对数均匀分布，约 30% 永久计入 F，其余是瞬时过冲、随后回吐（半衰期 1.5 个市场小时）；牛 / 熊 / 震荡三种市场状态按马尔可夫链切换，并带动溢价偏移（牛市 +、熊市 −）；成交量随波动率放大，与波动正相关。

每个合约的走势性格由 **波动率倾向** 五个数描述：日波动率、每日跳跃次数、跳跃幅度下限与上限、溢价偏移。各成分的强度由这五个数**闭式反推**（`Calibration`），使按市场日计的收益率标准差等于配置的日波动率，而不是靠调参碰运气；跳跃已经超过日波动率预算、日常扩散占比过低的配置会被拒绝。

**合约由服务端配置文件定义**（`config/creepercapital-contracts.json`）：交易代码、标的资源、起始价格、基础成交量、波动率倾向。文件不存在时自动生成内置的 DIAMONDCRP（起始 1000，日波动约 3%，跳跃少而小）和 GUNPOWDERCRP（起始 100，日波动约 10%，每日 1~3 次 5%~20% 的跳跃）。火药起始价格比 PRD 写的约 0.05 大得多，是因为界面目前统一显示 2 位小数，见 HUM_MEMO。配置有任何错误（JSON 损坏、没有合约、代码重复、缺字段、波动率兑现不了）时，整份回退到内置合约，并**不覆盖**用户的文件，只在日志里指出哪一个合约哪里错了。

**参数在配置、状态在存档**：改配置只改参数，下次启动生效；基本面价值、慢偏离、波动率比值、市场状态、排队中的跳跃、随机数状态等模型状态全部随世界存档保存，重启后接着走、不补算。每个合约有自己的随机数流（由市场种子和交易代码派生），所以增删合约不会改变其他合约的走势。配置里去掉的合约，状态原样留在存档里，重新加回去后接着走；新加的合约从起始价格开始。#6 及以前的单合约存档读出为 DIAMONDCRP，其余合约从起始价格开始。

**跳跃保留新闻挂接点**：行情步推进时，每次跳跃（随机或 `/creeper dev market jump` 手动）都会产生一个 `JumpEvent`（合约、行情步、变化比例、原因），由 `Market.addJumpListener` 订阅；首版只写日志，不展示新闻文字。

## Considered Options

- **纯几何布朗运动**：恒正、好调，但没有波动聚集、肥尾和跳跃，K 线看起来像白噪声；日内收益的绝对值也没有自相关。
- **参数全部手写进配置**（GARCH 系数、各状态漂移……）：太灵活也太难调，玩家改错一个就会发散。只暴露五个直观的数，由闭式校准保证日波动率兑现。
- **跳跃全部永久**：跳完价格不再回来，几天之内就会漂出合理范围；全部回吐则「消息」毫无后果。折中取三成永久。
- **合约写死在代码里**：新增一个合约要改代码重新发版，与「由 OP 在服务器上调整行情性格」的目标矛盾。
- **配置错误时跳过出错的合约**：玩家会静默地少一个合约，且存档里该合约状态与配置不一致；整份回退并明确报错更容易发现。
