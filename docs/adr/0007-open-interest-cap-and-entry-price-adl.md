# 持仓总量上限与以开仓价成交的自动减仓（ADL）

流动性池是所有玩家的唯一对手方（ADR-0001），所以玩家整体净赚多少，池子就净亏多少。两道防线保证池子付得起：**事前**限制每个合约的持仓总量，**事后**在池子权益为负时自动减仓。

**池子权益** = 池子现金 − 全体玩家仓位的未实现盈亏（按标记价格）。玩家盈利是池子欠的，玩家亏损是池子将收的，所以权益随玩家盈亏起伏。亏损的仓位最多算到它的保证金（池子最多收到这么多；超出的穿仓由强平和风险保障基金处理，见 #12），盈利的仓位不设上限；没有有效标记价格（合约已不在配置里）的仓位按 0 算。

**持仓总量上限（事前）**：每个合约各自一个上限 = 池子权益 × 该合约的 `open_interest_ratio`（可选配置，缺省 50%，旧配置文件不回写），权益不为正时上限为 0。**持仓总量** = 这个合约所有玩家持仓数量之和（多空都算正，毛额），按**这一笔成交的价格**估值。只有开仓和加仓受限：市价单、限价单挂单（用委托价）都检查，限价单成交时再检查一次（成交时池子权益可能已变），不通过就撤单（`FILL_REJECTED`，与保证金不足同一条撤单路径）。平仓、减仓、止盈止损、强平、自动减仓永远不受限，所以 OI 超过上限（权益下降）后玩家仍能离场。它与 #11 的单仓位名义价值档位上限同时生效，哪个先触到哪个拒单。各合约的上限都按同一个池子的权益算（首版全体合约共用一个池子），因此各合约上限之和可以超过池子权益——它是每个合约各自的上限，不是池子的总预算。

**自动减仓（事后）**：行情步的第 ④ 阶段（接在 ③ 强平之后：强平先把穿仓的亏损仓位收走，权益才反映真实缺口，免得白白减掉盈利玩家的仓位）检查池子权益；为负时按 **ADL 排名**依次缩减盈利仓位，直到权益不再为负。

- **排名**：全服所有盈利仓位（跨合约、跨方向，因为共用一个池子）按得分 = 盈利率（浮盈 / 保证金）× 杠杆 从高到低；同分按浮盈从大到小，再按玩家、合约，保证确定。亏损或持平的仓位不在排名里，永远不会被自动减仓。
- **以开仓价成交**：被缩减的部分按该仓位的**开仓均价**平掉，所以被减部分的浮盈归零（池子不用再付），保证金退回玩家可用余额，不收手续费，已实现盈亏恒为 0。玩家损失的是尚未兑现的浮盈，本金不动。池子现金不变，权益每步增加被缩减部分的浮盈。
- **最少手数**：最后一个被缩减的仓位只减到权益恰好回到非负所需的最少手数（对手数二分，权益回升量随手数单调不减）；其余仓位被整个减光。
- **总能恢复**：盈利全部抹掉后，权益 = 池子现金 + 亏损仓位的保证金 ≥ 0，所以不会出现减光了所有盈利仓位权益仍为负的情况。
- **守恒与余额**：玩家 + 池子 + 基金的总额不变（减仓只把保证金从仓位挪到玩家余额，池子一分钱不动）；玩家余额不会为负。
- **记录**：每次缩减是一笔 `TradeKind.ADL` 成交（成交历史里显示「自动减仓多 / 空」，品牌黄色），并产生结构化的 `AutoDeleverageEvent`（玩家、合约、数量、剩余、开仓价、标记价格、放弃的浮盈、退回的保证金、排名、成交编号），在线玩家收到通知，离线玩家记进离线事件汇总（#19，金额记成交额，因为已实现盈亏恒为 0，用成交额才能和成交历史对账）。

**ADL 指示灯**：仓位页每行五档，由服务端按同一份排名算好随交易状态同步（价格每个行情步都在变，每步重发）。灯数 = 5 − (名次 − 1) × 5 / 盈利仓位数（整数除法）：盈利仓位按名次五等分，最靠前的五分之一亮 5 格，往后依次 4、3、2、1；只有一个盈利仓位时它亮 5 格。**亏损或持平的仓位显示最低的 1 格**（它不在排名里、永远不会被减，1 格是最低档的显示而不是“有风险”）。指示灯与自动减仓的执行顺序读的是同一份排名，所以两者必然一致，有测试逐项核对。

**残余的最后防线（`payUpTo`）**：权益 ≥ 0 并不意味着池子现金够付单个赢家平仓的全额——亏损仓位的保证金还没收进池子（玩家没平仓、没被强平）。此时平仓 / 强平 / 资金费结算仍按“池子付得出多少付多少”（`payUpTo`），不会让池子为负，但玩家少收的部分不会走 ADL 事件。这是 #12 留下的临时处理的延续：ADL 把它收窄到“权益为正但现金暂时不足”这个窄窗口，没有消除；彻底消除需要在平仓前预收亏损方的保证金，成本和复杂度不匹配首版。

## Considered Options

- **每个合约、每个方向各一份排名（常见做法）**：常见做法是每个合约有独立的保险基金和对手方池，排名按合约多空分开。这里全服共用一个池子，某合约的盈利会被另一个合约的亏损抵消，按合约分开排会减掉不该减的仓位，所以排名是全局的。
- **按标记价格成交的自动减仓**：被减部分按市价兑现盈利，池子还是要付，只是付得更早，解决不了偿付问题。开仓价成交让池子“少付”而不是“付给别人”，是唯一能直接补回权益的做法。
- **按持仓比例对所有盈利者均摊**：公平但每个人都被减一点，指示灯没有意义；按排名先减得分最高的，高杠杆高收益者承担更多，与风险承担一致。
- **让池子为负（允许透支）**：违反“池子是有限资金的对手方”的前提，且负余额无处追偿。
- **持仓总量上限用名义价值的净额（多空相抵）**：多空相抵后池子的敞口确实更小，但净额随价格和玩家行为剧烈波动，会让玩家今天能开明天不能平衡；毛额简单、可预期、单调。净额上限可作为后续调整，留作以后的决策。
- **上限用固定数额而不是随池子权益变化**：玩家整体盈利时池子权益缩水，固定上限不会收紧，起不到保护作用；随权益变化让上限在池子吃紧时自动收紧，在池子充裕时放宽。
- **自动减仓在强平之前**：穿仓的亏损仓位还没收走，权益被高估为更负，会多减盈利者的仓位。
